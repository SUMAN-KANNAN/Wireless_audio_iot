=======================
HOW TO RUN THIS PROJECT
=======================

This document provides instructions for setting up and running the Wireless Audio Control System.
The project consists of a Python Flask server and firmware for ESP32 devices.

-----------------------
SECTION 1: FIRMWARE SETUP (FOR REAL ESP32 HARDWARE)
-----------------------
Follow these steps once for each physical ESP32 device. The firmware is located in the `esp32_firmware/firmware/` directory.

1.  **Add ESP32 Board Support:**
    a. Open the Arduino IDE and go to `File > Preferences`.
    b. In "Additional Boards Manager URLs", paste:
       `https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json`
    c. Go to `Tools > Board > Boards Manager...`, search for "esp32", and click "Install".

2.  **Install Required Libraries:**
    a. **ArduinoJson:** In the Arduino IDE, go to `Tools > Manage Libraries...`, search for `ArduinoJson`, and install the one by Benoit Blanchon.
    b. **WebSockets:** In the Arduino IDE, go to `Tools > Manage Libraries...`, search for `WebSockets`, and install the one by Markus Sattler.

3.  **Configure and Upload Firmware:**
    a. **Important:** Do not copy the `.ino` file to another location like your Downloads folder. You must open the original project directly from its folder.
    b. In the Arduino IDE, go to `File > Open...`
    c. Navigate to this project's `esp32_firmware/firmware` folder and open the `firmware.ino` file.
    d. **A second tab named `secrets.h` should now open automatically.** Fill in your WiFi `ssid`, `password`, and the `device_api_key`.
    e. In `firmware.ino`, set the `THIS_ROOM_ID` variable to match the room this device will represent (e.g., "conferenceRoom").
    f. **Note on Battery:** By default, the firmware simulates a random battery level for easier testing. If you have a physical battery circuit, you can enable the real battery reading by following the comments in the `loop()` function of `firmware.ino`.
    g. **Crucial:** In `firmware.ino`, find the `websocket_server_address` variable.
       You must change this IP address to match the IP of the computer running the Python server.
       When you run `python app.py`, the server will print its IP address in the terminal.
       For example: `* Running on http://192.168.1.114:5000`. You must use that IP address (`192.168.1.114` in this case).
    h. Go to `Tools > Board > ESP32 Arduino` and select `ESP32 Dev Module`. This is the correct choice for most common boards, including the ESP32 DevKitC V1.
    i. Connect your ESP32, select the correct Port under `Tools`, and click the "Upload" button.

4.  **Troubleshooting Upload Errors:**
    If you see an error like `A fatal error occurred: Failed to connect to ESP32: Wrong boot mode detected`, it means the board did not automatically enter "Download Mode".
    Most ESP32 DevKits handle this automatically, but sometimes you need to do it manually.

    **To enter Download Mode manually (try Method 1 first):**

    **Method 1 (Easiest):**
    a. In the Arduino IDE, click the "Upload" button.
    b. As soon as you see the "Connecting........" message in the console, press and **hold** the "BOOT" or "IO0" button on your ESP32 board.
    c. Release the button once the upload starts (when you see the progress percentage).

    **Method 2 (If Method 1 fails):**
    a. Unplug your ESP32 from the computer.
    b. Press and **hold** the "BOOT" or "IO0" button on the board.
    c. While still holding "BOOT", plug the ESP32 back into your computer.
    d. Release the "BOOT" button.
    e. In the Arduino IDE, re-select the correct COM port (it may have changed).
    f. Click the "Upload" button again. The upload should now succeed.

    After a successful upload, you may need to press the "RESET" or "EN" button to make the board run the new code.

5.  **Troubleshooting "Device Not Connecting":**
    If your Serial Monitor shows a loop of "Attempting to connect...", it's almost always a firewall issue on the computer running the server.

    **To fix this on Windows:**
    a. Open the Start Menu and search for "Windows Defender Firewall".
    b. On the left, click "Allow an app or feature through Windows Defender Firewall".
    c. Click "Change settings" (you may need admin rights).
    d. Click "Allow another app...".
    e. Click "Browse..." and find your Python executable. If you are using the virtual environment from this guide, it will be located at:
       `C:\Users\rayud\Desktop\Wireless Full\Wireless working S & R\venv\Scripts\python.exe`
    f. Click "Add".
    g. Make sure that for the newly added "Python" entry, both the **Private** and **Public** checkboxes are ticked.
    h. Click "OK".

SECTION 2: RUNNING THE SERVER & VIRTUAL DEVICES (FOR DEVELOPMENT)
------------------------------------
Use these steps to run the application on your local machine for testing.

1.  **Install Python Dependencies:**
    a. Ensure you have Python 3 and pip installed.
    b. Open a terminal in the project root directory.
    c. Create a virtual environment (recommended):
       `python -m venv venv`
       `.\venv\Scripts\activate` (on Windows) or `source venv/bin/activate` (on macOS/Linux)
    d. Install the required packages:
       `pip install -r requirements.txt`

2.  **Set Environment Variables (Optional but Recommended):**
    For better security, you can set the API key as an environment variable.
    - On Windows (Command Prompt): `set DEVICE_API_KEY=a-super-secret-and-unique-key`
    - On macOS/Linux: `export DEVICE_API_KEY="a-super-secret-and-unique-key"`

3.  **Start the Flask Server:**
    In your terminal, run:
    `python app.py`

4.  **Run Virtual ESP32 Devices (for testing without hardware):**
    a. Open **three separate terminals**.
    b. In each terminal, run the virtual client script with a different room ID:
       `python virtual_esp32.py conferenceRoom`
       `python virtual_esp32.py adminRoom`
       `python virtual_esp32.py classRoom`
    c. **New Feature:** The virtual devices are now interactive. In each terminal, you can
       press the **'m' key followed by 'Enter'** to toggle the microphone ON and OFF for that room.

5.  **Access the Dashboard:**
    Open your web browser and go to `http://127.0.0.1:5000`.
    Log in with default credentials: `admin` / `password` or `user` / `123`.


------------------------------------
SECTION 3: RUNNING WITH REAL HARDWARE
------------------------------------

1.  Complete the **Firmware Setup** from Section 1 for your device(s).
2.  Start the **Flask Server** as described in Section 2, Step 3.
3.  Power on your ESP32 device(s) (or press the "RESET" / "EN" button if it's already plugged in).
4.  **Verify Operation with Serial Monitor:**
    a. In the Arduino IDE, go to `Tools > Serial Monitor`.
    b. Make sure the baud rate in the bottom-right corner is set to `115200`.
    c. You should see messages indicating it's connecting to WiFi and then to the WebSockets.
    d. After connecting, the device should remain stable and periodically send its battery status. It should NOT enter a reboot loop.
5.  Access the dashboard to see the real devices connect and report their status.


------------------------------------
SECTION 4: PRODUCTION DEPLOYMENT (ADVANCED)
------------------------------------
The Flask development server is not suitable for production. Use a production-grade
WSGI server like Gunicorn with a gevent worker to handle WebSockets efficiently.

1.  Ensure all dependencies from `requirements.txt` are installed.
2.  Run the application using the following command (on Linux/macOS):

    `gunicorn --worker-class geventwebsocket.gunicorn.workers.GeventWebSocketWorker -w 1 --bind 0.0.0.0:5000 app:app`

    **Note on the worker class:** The `--worker-class geventwebsocket...` is crucial.
    Standard web server workers are designed for short HTTP requests. This special
    worker uses asynchronous I/O to efficiently manage many long-lived WebSocket
    connections simultaneously, which is essential for this application's real-time features.

SECTION 5: PUSHING CODE TO GITHUB
------------------------------------
These instructions explain how to push your local code changes to the project's GitHub repository.

**Prerequisites:**
- You must have Git installed on your computer.
- You must have configured Git with your GitHub username and email.
- You must have the correct permissions to push to the repository.

**One-Time Setup (for the first time pushing from this folder):**
1. Open a terminal (like Git Bash, Command Prompt, or PowerShell) in the project's root directory.
2. Initialize a Git repository if you haven't already:
   `git init`

3. Add the GitHub repository as the "origin" remote:
   `git remote add origin https://github.com/SUMAN-KANNAN/Wireless_audio_iot.git`

   (If you get an error that "origin" already exists, you can update it with `git remote set-url origin https://github.com/SUMAN-KANNAN/Wireless_audio_iot.git`)

**Pushing to a Specific Branch (e.g., "Sabarish"):**
These steps will replace the entire content of the remote "Sabarish" branch with your local files.

1. Create and switch to a new local branch named "Sabarish":
   `git checkout -b Sabarish`
   (If the branch already exists, you can switch to it with `git checkout Sabarish`)

2. Stage all your local files for the commit. This command respects the `.gitignore` file.
   `git add .`

3. Commit your changes with a descriptive message:
   `git commit -m "Sync local project state to Sabarish branch"`

4. Push your local branch to GitHub, overwriting the remote branch.
   **WARNING:** The `-f` or `--force` flag is destructive. It will replace the remote branch with your local version. Only use this if you are sure you want to overwrite the history on that specific branch.
   `git push -f origin Sabararish`
